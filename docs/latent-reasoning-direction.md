# 論文與社群資料對 Qwen3.8 HybridAgent 研究方向的影響

整理日期：2026-10-21  
對應程式版本：`qwen38-compat` 分支；聯合更新 `40fef11`、已完成的補測 `2f37602`。
研究狀態：LoRA＋Link 已完成一次八筆平均更新並保存，補測與重載重現通過。接著準備同目標、只更新 Link 的單步對照；目前只授權實作與測試發布，對照的 GPU 執行需另外確認。

## 一、結論先行

目前已建立的證據是：**系統跑得通，HybridLink 的局部預測學得動；尚未證明模型能用連續向量完成完整推理並自然退出。**

外部資料對方向的主要影響：

- **不能把「只更新 Link」視為官方完整方法。** HybridAgent 官方另有主模型與 Link 共同學習使用預測向量的階段；我們目前僅完成受限 LoRA＋Link 單步實驗，並非官方完整訓練重現。
- **凍結主模型仍是可研究的方向，但不是已驗證的捷徑。** INTACT 提供相關先例，使用的模組、訓練目標與成功標準卻不同。
- **局部預測、完整推理、自然退出要分開衡量。** 平均誤差下降或答案正確，都可能掩蓋後段退步或文字重新計算。
- **完整輸入與 cache 的數值差異應獨立調查。** Qwen 社群有相近案例，但目前不足以把我們的失敗歸因於 cache 程式錯誤。

最值得優先釐清的問題，不是單純「要不要多訓練幾步」，而是：**我們要繼續探索凍結主模型的替代方法，還是朝官方聯合訓練靠近？** 本文保留原先的方向比較；後續已選擇先以 LoRA＋Link 小規模實驗靠近官方聯合訓練，而非直接做全參數訓練。

限制：

- 更新組、觀察組與剩餘訓練資料都參與過更早階段的訓練，不能稱為未見資料測試。
- 保留的 latent test 尚未評估。
- 完整向量診斷仍無自然退出成功，強制退出後還會用文字重新計算。
- 完整診斷的參考位置從 0 起算，且是在餵入該位置向量前測量；三／六輸入實驗的步數從 1 起算，是餵入相應數量的預測向量後測量，兩者不能直接混用。
- 三輸入八次更新與六輸入單次更新，更新次數和參與資料不同，不能直接判定哪個訓練方法較好。

## 三、HybridAgent 官方：初始對齊不是完整訓練

### 來源說了什麼

官方 README 分成三個階段：

1. **格式啟動**：訓練主模型學習 hybrid 格式與進入／退出標記。
2. **HybridLink 啟動**：固定主模型，讓 Link 預測目標輸入 embedding。
3. **Self-conditioned HybridSFT**：共同訓練主模型與 Link，讓模型學習使用自身產生的向量輸入。

論文 Appendix B.1 特別指出：前兩階段使用正確文字的 embedding 作為輸入，但生成時會反覆使用自身預測向量。連續向量不像文字 token 那樣，每一步都重新落在固定詞表的 embedding 上，因此輸入偏差可能沿軌跡累積。

官方程式採兩遍計算：先在正確文字輸入下產生預測向量，再把這些向量替換進第二遍輸入。第二遍同時使用文字預測與向量對齊目標，並另有針對退出標記的向量對齊項目。

### 對我們方向的影響

這是目前最直接解釋「前段改善、後段仍失敗」風險的來源。它使得「主模型尚未學會穩定使用預測向量」成為值得驗證的假設。

但我們後來的三／六步實驗已經把預測向量逐步接回，因此不能再把目前狀況簡化成「完全沒接觸過自己的輸出」。真正仍存在的差別包括：

- 主模型與 LoRA 固定，只有 Link 更新。
- 訓練只涵蓋開頭三／六步，不是完整推理與退出。
- 我們逐步產生下一個向量；官方兩遍方法的替換向量來自正確文字歷史，並非同一種逐步自由生成。
- 訓練目標不同：我們近期測試著重局部下一 token 預測；官方另含向量對齊與退出相關目標。

**不能推出的結論：**解凍主模型必然解決問題，或官方兩遍方法完全消除了所有生成時的分布差異。

**可參考的方向：**先比較訓練目標、參與更新的參數與完整軌跡覆蓋範圍，再決定是否設計 LoRA 加 Link 的受限聯合訓練。LoRA 版本仍是我們的改編，不等同官方全主模型訓練；顯存與相容性也尚未驗證。

來源：[論文 §4.1、Appendix B.1](https://arxiv.org/html/2610.18861) · [官方 SFT README](https://github.com/togethercomputer/HybridAgent/tree/main/hybrid_sft) · [官方實作](https://github.com/togethercomputer/HybridAgent/blob/main/hybrid_sft/model.py)

## 四、INTACT：凍結主模型的方向值得保留，但需比較訓練目標

### 來源說了什麼

INTACT 使用小型外部 encoder，根據固定主模型的隱藏狀態產生連續向量區塊：

- 先透過蒸餾，學習重現文字推理對主模型造成的效果。
- 再依答案正確性進行強化訓練。
- 向量前綴之後，主模型仍可繼續文字推理與作答。

作者在 1B 至 8B 的四個固定主模型上報告改善；這不是我們的 Qwen3.8-27B 組合。

### 對我們方向的影響

它反駁的是「固定主模型必然沒有研究價值」，而不是證明我們目前的 Link 架構與局部 CE 目標已足夠。

若保留凍結路線，值得研究的是：**除了讓下一個 token 更像答案，是否還需要訓練向量對後續計算造成的效果？** 這與直接模仿單一 token embedding、或只降低開頭幾步 CE，是不同問題。

重要邊界：INTACT 允許後續文字推理，因此它的成功標準與我們要求的「向量段已完成計算、自然退出」不同。不能直接拿它的答案準確率來宣稱我們的嚴格目標已被證明可行。

來源：[INTACT: Inducing Latent Reasoning on a Frozen Backbone](https://arxiv.org/html/2610.19568v1)

## 五、Latent reasoning 分析研究：答對與真的使用向量必須分開

### 來源說了什麼

《How Do Latent Reasoning Methods Perform Under Weak and Strong Supervision?》分析多種 latent reasoning 方法，發現在部分任務中，即使移除 latent steps，答案準確率仍很高。

研究指出模型可能依靠其他線索作答；中間向量包含資訊，也不代表整個計算過程忠實執行了預期的逐步推理或搜尋。

### 對我們方向的影響

它支持目前保守的解讀：**強制退出後答對，尤其又用文字重算，不能當成向量段已完成運算的證據。**

未來評估應分成兩層：

- **行為是否成功**：真正使用向量、格式完整、自然退出、答案正確，且沒有強制介入。
- **成功是否依賴向量中的資訊**：移除或適當干預向量後，結果是否按預期改變。

即使自然退出並答對，也仍需要第二層證據，才能更有把握地說模型依賴向量完成推理。反過來，粗暴干預造成失敗也可能只是破壞輸入，不能單獨當成因果證明。

這份研究沒有直接測試我們的模型，不應把其中的捷徑行為當成對本案的確診。

來源：[How Do Latent Reasoning Methods Perform Under Weak and Strong Supervision?](https://arxiv.org/html/2602.22441)

## 六、Qwen 社群討論：數值差異與訓練問題分開處理

這部分是工程討論，不是論文，也不是本案的已驗證修正。

### 最相關的案例：Transformers #46190

該討論比較 Qwen3.5 完整序列計算與先處理前文、再使用 cache 接一個 token 的輸出。

原報告稱 BF16 與 FP32 都有相同差異；後續貢獻者發現當時載入器忽略指定精度，所謂 FP32 測試仍在使用 BF16。真正轉成 FP32 後，其小模型重現的最大差異降至約 `3×10⁻⁵`。後續分析支持該重現中的 BF16 捨入與運算順序解釋，而非兩條路徑必然有演算法錯誤。

這對我們有關聯，因為 Qwen3.8-27B 官方設定仍使用 `qwen3_5` 架構；但模型大小、硬體、版本與輸入不同，不能把其結論直接搬過來。

### 另一個案例：#45513

該修正處理「已有 cache，卻一次接入多個 token」時未正確使用先前線性注意力狀態的問題。我們目前的診斷逐 token 接入，不符合這個已知問題的主要觸發條件。

### 對我們方向的影響

- 保留完整輸入與 cache 兩條路徑的獨立報告。
- 區分「相同路徑儲存／重載可精確重現」與「不同路徑數值完全相同」。前者通過不代表後者成立。
- 如需精度對照，必須檢查實際權重與運算精度，不能只相信載入參數。
- 不因社群案例就更新套件、安裝 kernel 或放寬既有驗證門檻。
- 不把 27B 全模型轉 FP32 當成可直接在目前單張 A100 上執行的步驟；資源需求需另行評估。

來源：[Transformers #46190，含後續更正](https://github.com/huggingface/transformers/issues/46190) · [#45513](https://github.com/huggingface/transformers/issues/45513) · [Qwen3.8-27B 設定](https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/config.json)

## 七、方向比較與後續選擇

1. **朝官方聯合訓練靠近。**
   - 優點：直接處理主模型未適應預測向量的假設，官方方法依據最直接。
   - 代價：LoRA 加 Link 的訓練需重新驗證；顯存、穩定性與原本文字能力都要檢查。
   - 限制：不是已知修正，也不能假設照搬官方兩遍方法就會自然退出。

2. **保留凍結主模型，研究不同的 Link／encoder 訓練目標。**
   - 優點：維持主模型不變，便於隔離向量模組的影響；INTACT 提供相關先例。
   - 代價：方法改動與研究不確定性較大，可能需要蒸餾或答案層級訓練。
   - 限制：不能只引用 INTACT，就認定局部 CE 多跑幾次會達成相同效果。

3. **先做受控比較，不擴大訓練。**
   - 優點：先把三／六輸入訓練放在相同六位置測量下比較，並保留兩條執行路徑，可降低誤判。
   - 代價：主要增加診斷把握，不直接解決完整推理與退出。
   - 限制：訓練次數與參與資料若仍不同，結果只能描述各檢查點，不能隔離「三步對六步」的因果效果。

**原先建議：**先釐清第三項的比較設計，再決定第一或第二項；長期訓練方向優先評估第一項。

**後續決定與結果（使用者回報的 Colab 證據）：**保留 Qwen3.8-27B，先完成無更新反向傳播探測，再完成一次 LoRA A/B＋Link 聯合更新；原始文字／視覺權重與進出標記固定。兩遍目標保留第一遍梯度，不是上游第一遍 `no_grad` 的完全重現。

- 原始單步執行在保存後因 tokenizer 載入旗標比較停止，未測得當時記憶體內的更新後指標。沒有重跑更新；`evaluation-r2` 從已保存權重補測，原始 16 題與保存權重的重載均完全重現。此前一次補測因校準副本的來源雜湊被重算而停止，也保留了失敗紀錄。
- 更新／觀察組兩遍總誤差分別由 `0.513740 → 0.441357`、`0.511156 → 0.472362`；六步快取平均 CE 由 `2.414293 → 2.150165`、`2.739345 → 2.442512`。六步全對仍為 `1/8`、`0/8`。兩遍總誤差下降主要來自文字／錨點預測項，不能直接歸因於 LoRA。
- `67×7−18` 第 3–5 步修正，但第 6 步仍錯且 CE 上升；`65×7−7` 快取第 3 步由正確空白變成 `" is"`，正確機率約 `56.2% → 1.27%`。完整重算也失去該題原本正確的第 3、4 步。
- 16 題自然退出仍 `0/16`，全部強制退出；混合答案 `16/16`，格式／嚴格成功仍 `0/16`。普通文字 `14/16`、指定格式 `16/16`，前後不變。所有題目參與過先前訓練，不能宣稱泛化。
- 補測沒有更新或匯出權重；峰值配置顯存 `56.211489 GiB`，約 `2793.94` 秒。這不是原訓練成本，也不能證明原執行未測量的即時更新後指標。原始骨幹只做版本／無梯度檢查，未逐位元組比較。

**下一項受控比較：**從原始 `qwen-link-64` 開始，同樣前 8 題更新、後 8 題觀察、兩遍目標、一次 `5e-6` AdamW 更新；只凍結 LoRA，不切斷模型對 Link 輸入的梯度。保持訓練模式與精度，16 題原始測量需先完全重現。裁剪上限相同，但參數集合不同，會記錄裁剪前大小，不假設 Link 更新幅度相等。保存與重載後逐題比較兩條路徑、六個位置、退出及文字能力；不打開保留測試集、不接續聯合權重、不擴大訓練。

## 八、無論採哪個方向，都維持的判準

- 不只報平均 CE；保留每題、每位置、正確變錯誤，以及後段退步。
- 不把前三／六步正確當成完整向量推理成功。
- 自然退出與完整推理需另行評估，不能從開頭短段訓練推論。
- 正確前綴、參考向量、已知長度與強制退出，只作為診斷條件，不算自主能力。
- 不把訓練資料的改善描述為未見資料泛化；保留測試集繼續不開封。
- 固定來源權重、資料、精度與執行條件；不依結果挑最佳檢查點，不覆寫原始輸出。
- GitHub 保存程式不代表保存了 Colab 權重與紀錄；恢復前仍需確認備份與校驗值。使用者已於新 Colab 回報備份 SHA256 校驗通過、還原完成，並核對訓練資料、原始 Link／LoRA 與六步更新 Link 的檔案雜湊；原有 70 項測試全部通過、無跳過。備份 SHA256 為 `2f9818d8294b76ccb8251af2be8f89ad60cd940161e3abe0e23d619fe7328420`。

使用者另確認新實驗增量備份完成：`20261021T083221Z-lora-joint-8e6a319f/lora-joint-artifacts.tar.gz`，32 個檔案，SHA256 `e4fede77a9a5a009bfeb9f7b6133ada4c1a795bd8af6e8e2fcf66cf0f0338522`。壓縮包逐檔雜湊與來源複查通過；包含 LoRA＋Link 新權重、補測與失敗紀錄。它依賴前述舊備份，不能單獨還原全部實驗。

## 九、待追蹤與未知事項

- 查閱時，HybridAgent 官方 issues 未找到直接對應我們這組現象的解法：[官方 issues](https://github.com/togethercomputer/HybridAgent/issues)。此狀態可能改變。
- 尚未確認主模型適應不足、局部訓練目標、軌跡長度與數值差異各自造成多少影響。
- Qwen3.8 的 self-conditioned LoRA＋Link 已驗證反向傳播及單次更新／保存／重載；仍未證明完整自然退出或未見資料泛化，也尚無同目標 Link-only 結果。
- 沒有外部來源能證明目前六步單次更新的後段退步，只要增加訓練次數就一定會消失。

**總結：這些資料使我們更有理由重新檢查訓練方式與成功判準，而不是直接把「多跑幾步」當成解法。**
